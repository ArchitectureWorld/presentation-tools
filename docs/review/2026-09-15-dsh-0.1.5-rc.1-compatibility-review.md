# 2026-09-15 — Report Studio / DSH 0.1.5-rc.1 Compatibility Review

## Scope

Target repository: `ArchitectureWorld/presentation-tools`  
Target branch: `feat/report-studio-v0.2.0-layout`  
Review base: `ed5f81d005d093e90d6f5f83541f57025eef7d1a`  
Report Studio: `0.2.0-alpha.3`  
Plugin package: `@architectureworld/report-studio-dsh@0.1.1`  
Target DSH: `0.1.5-rc.1`  
Node baseline: `>=24.11.0`

This review updates the active development branch only. Historical acceptance/handoff records that accurately state an older tested DSH version remain historical evidence and are not rewritten to pretend they were executed on `0.1.5-rc.1`.

## Conclusion

The v0.2.0 layout branch does **not** require a rewrite of the Report Studio Host architecture, but it does require a real DSH compatibility upgrade. The material breaking point is the Web Client dependency graph: the branch still declared the removed legacy `@deepseek-ai/dsh-client-runtime` dependency while DSH 0.1.5 uses domain-scoped Client packages and Session Controller.

The following existing integration points remain structurally valid for 0.1.5 and are intentionally retained:

- Host `ctx.sessions` and `SessionHeader.cwd`;
- Cordis `session/event` and `session/disposed` events;
- tool execution `exec.agent` identity (not removed `ctx.agent`);
- Client `ctx.sessions`, stable `sessions.binding(sessionId)` and `session.prompt(content, 'queue')`;
- `conversation.view` and `conversation.session.header.actions` slots;
- Host `ctx.llm` for the isolated review worker;
- loopback-only `/report-studio` Host `webServer` route.

Report Studio does not iterate the removed `session.events` array and does not parse DSH Session persistence. Session V3 therefore changes DSH migration/rollback operations, but does not require a Studio Repository schema migration.

## Required compatibility changes

### 1. Browser module graph

Old declaration:

```text
@deepseek-ai/dsh-client-runtime
@deepseek-ai/dsh-client-ui-conversation
```

0.1.5 target declaration:

```text
@deepseek-ai/dsh-api-remotes
@deepseek-ai/dsh-api-session-controller
@deepseek-ai/dsh-client-ui-conversation
@deepseek-ai/dsh-client-ui-renderer
@deepseek-ai/dsh-client-ui-session
```

The Report Studio client itself only requires React at runtime, but these injected packages establish the Session model, Session scope adapter, Conversation slot declarations, rendering path and Remote assembly expected by the 0.1.5 Web composition.

### 2. Runtime/version gate

The branch already requires Node `>=24.11.0`, so no Node downgrade/upgrade change is needed. This baseline is also safely above the Node versions where DSH 0.1.5 CLI startup can fail because `import.meta.main` is unavailable.

`smoke:dsh` is changed from merely executing `dsh --version` to requiring a non-empty `0.1.5-rc.1` version result. A silent exit with status 0 is a failure.

### 3. CI pin

The convergence CI must install exactly:

```text
@deepseek-ai/dsh@0.1.5-rc.1
```

Artifact evidence must record the same version. Linux and Windows smoke must run the plugin tarball produced by the current checkout, not a tracked `dist` fallback.

### 4. Session V3 deployment boundary

Before the first `0.1.5-rc.1` start against an existing DSH home:

- stop all DSH processes;
- cold-backup the complete `DSH_HOME`;
- keep Report Studio data backup separately;
- do not treat package downgrade alone as a Session rollback;
- avoid performing first V3 migration directly on exFAT, unreliable FUSE mounts, or network/NAS-mapped paths lacking native local filesystem semantics.

Report Studio A1.1 migration remains independent from DSH Session V3 migration.

### 5. Security boundary

No compatibility evidence justifies relaxing the existing security model. `securityMode=local-single-user-only`, loopback listener enforcement, and the rule that query `sessionId` is not authentication remain unchanged.

DSH 0.1.5-rc.1 has a known `client-connection` third-party `rpc.handle()` regression. Report Studio does not use that path for its HTTP API; it registers `/report-studio` directly on Host `webServer`. This does not guarantee other plugins in the same Profile are unaffected.

## Compatibility checks added

Static verification now rejects:

- reintroduction of `@deepseek-ai/dsh-client-runtime`;
- use of removed Host `ctx.agent`;
- direct use of removed `session.events`;
- drift from DSH `0.1.5-rc.1` compatibility metadata;
- drift from Node `>=24.11.0`;
- drift from the new Web Client package graph.

Smoke verification now rejects:

- empty `dsh --version` output;
- a DSH version other than `0.1.5-rc.1`;
- missing current tarball path;
- plugin composition missing from `--dump-config`;
- failure to create/open the smoke Session and Report Studio health route.

## Host services still requiring real target proof

`apiProxy` is retained for the isolated review worker's current Session model resolution path because the branch already depends on it. DSH 0.1.5 is moving Client/Remote architecture toward controller-owned Remote namespaces, but this review does not replace a working Host seam speculatively. The exact target smoke/CI must prove the current `apiProxy.sessions.models` path remains composed in `0.1.5-rc.1`; if that gate fails, the next change is to move model resolution to the current Session Controller/Remote seam rather than adding a second Agent runtime.

Likewise, the legacy `/api/session.create` envelope in the smoke harness is retained until the real `0.1.5-rc.1` smoke proves or disproves it. A failure there is an API-adapter issue, not permission to weaken the smoke.

## Current gate status

Do not call the branch `0.1.5-rc.1 verified` until those jobs pass and a real DSH + Pre-design + Provider acceptance run is recorded.
