# Report Studio v0.1.0 Outline + Draft Usable Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a locally deployable Report Studio v0.1.0 whose Outline and Draft stages are directly usable with persistent projects, ReviewRound multi-submission review, Proposal/Revision application, and a DSH-ready adapter boundary; Layout implementation is deferred to v0.2.0.

**Architecture:** Build a small TypeScript workspace around stable contracts and a pure domain core, then connect it to a React UI that preserves the v0.8.1 interaction baseline. Persistence and DSH integration remain behind adapters so the first usable slice can run locally without inventing a second Agent runtime.

**Tech Stack:** TypeScript 5.x, React 18, Vite, Zod 4, Vitest, pnpm workspace, Node.js 22+.

**Spec:** `docs/architecture/report-studio-mvp-baseline-v0.1.0.md`

## Global Constraints

- Product version is exactly `v0.1.0`.
- v0.1.0 production scope is Outline + Draft + annotations + ReviewRound/ReviewSubmission + persistence/recovery + Agent adapter boundary.
- Layout is visible only as a deferred v0.2.0 entry and must not block v0.1.0.
- Current MVP has no `pre-design` dependency.
- DSH Harness remains the only production Agent/model runtime.
- One `ReviewRound` may contain multiple immutable `ReviewSubmission`s.
- Agent output never automatically resolves an annotation.
- Stable IDs never use array indices, DOM order, or editor-private paths.
- UI does not directly write storage.
